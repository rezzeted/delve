# Демо-подземелье

Пример проекта Delve (формат `delve-project/1`) для превью в DelveViewer.
Папка самодостаточна (R-P0): слот-ассеты подтягиваются из библиотеки
`assets/` репозитория по обычному порядку корней (R-A5) — локальных ассетов
в проекте нет.

## Открыть

```
DelveViewer projects/demo/project.json
```

или без параметров: запустить `DelveViewer` и выбрать этот файл через
Browse / перетащить в окно.

## Что внутри

Граф (8 комнат, 7 связей):

```
entry ─c1─ hall ─c2─ [crypt]   (ворота gate)
            │
            ├─c3─ [vault]      (ворота gate, L-образный зал, тег treasure)
            │
            └───── stairs
```

Витрина возможностей (что посмотреть во вьювере):

- **L-зал vault** — явный шаблон `vault_L` (фигурный контур 10×6 с выемкой,
  4 поворота); прямоугольные комнаты порождаются из `rooms_rect` (entry,
  crypt, stairs), коридоры — параметрические 2×(3..5).
- **Ворота с решёткой** — связи `gate` до crypt и vault (тип двери доезжает
  из графа до юнита).
- **Переходы камень|кирпич** — на каждом стыке коридор/комната (side_rule
  `adjacent_role=corridor` → brick; узор `chase`, по углам).
- **Происхождение значений (F12)** — клик по комнате: у `stairs` высота 4.0
  переопределена на уровне комнаты, у `vault` — на уровне шаблона (3.6),
  остальные — роль/`*`/проект. В инфо-панели видна вся цепочка.
- **Разные высоты** — entry 2.8, crypt 2.4, залы 3.0–3.6, stairs 4.0.

## Потрогать инкрементальность (F8)

1. Открыть проект, дождаться fill (~8 с в Debug).
2. Поменять в `project.json` параметр наполнения (например, `crypt.h`
   2.4 → 3.0 или `door_h`).
3. Refill во вьювере — в логе видно, что пересчитались только юниты с
   изменённым входом (`reused`/`reran`).
4. Re-layout — раскладка заново (тот же seed); неизменённые юниты — из кэша.
