# Delve: превью F9 v1 (DelveViewer)

`src/apps/DelveViewer`: приложение превью уровня (requirements §7, F9) — 3D-вид
и вид сверху с наложением IR поверх наполненного уровня. Своя логика только в
приложении (N4): библиотеки `delve*` не трогает, рендер — `pgg_preview`
(оффскрин sokol + орбит-камера), панели и оверлей — Dear ImGui. Тесты: два
smoke-прогона в ctest (`DelveViewer_smoke_layout`, `DelveViewer_smoke_ir`).

## CLI

```
DelveViewer [project.json [--ir frozen.json]] [--smoke]
```

- Без аргументов: открывается окно с пустым состоянием; проект открывается из
  панели Open (поле пути + список недавних за сессию, опциональное поле
  IR-файла) или drag-and-drop .json на окно. Кнопка Open неактивна, пока поле
  проекта пустое; ошибка загрузки — красным текстом в той же панели. У полей —
  кнопки «Browse…»: модальный файловый диалог на чистом ImGui (`filedialog.h`,
  без нативных зависимостей): текущий каталог + Up, сначала каталоги
  (`[dir] …`, клик — войти), затем *.json (клик — выбрать, двойной клик —
  принять), редактируемое поле полного пути (Enter = Select), Select/Cancel,
  Esc закрывает; старт — каталог последнего выбранного файла этого поля,
  иначе cwd (память на сессию). Выбор в диалоге лишь заполняет поле — загрузка
  по-прежнему по Open. Относительные пути из панели ищутся сначала от cwd,
  затем от каталога последнего открытого проекта.
- Drag-and-drop (где платформа позволяет; на X11 — через Xdnd): снифф по
  подстроке `"delve-ir/` в голове файла — это IR, иначе проект. Дроп проекта
  открывает его (заменяя текущий уровень); дроп IR при загруженном проекте
  перезагружает уровень с этим IR (в пустом состоянии — ошибка «drop a project
  first»); два файла за один дроп — проект + IR вместе.
- Без `--ir`: раскладка генерируется из layout-яруса проекта
  (`build_catalog` → `LayoutGenerator`, attempts=4 → `build_ir_from_layout`).
- `--ir <file>`: вместо генерации читается замороженный IR; формат
  определяется по ключу `format`: `delve-ir/0` собирается через проект
  (`build_ir_v2`), `delve-ir/2|3` читается напрямую (`read_ir_v2_json`).
- `--smoke`: тот же путь данных без окна и sokol (покрытие в ctest без GPU):
  одна строка статистики в stdout, exit 0; без проекта — usage + exit 2.
- Коды выхода: 0 — ок, 1 — ошибка данных (проект/IR/fill), 2 — ошибка
  командной строки.

Наполнение — `fill_level` с живым `UnitCache` (F8), активы Delve ищутся по
`assets/codes.pgg`: `./assets` от cwd, затем вверх от каталога исполняемого
файла, затем вверх от каталога проекта; слоты проекта дополнительно
отваливаются в `FillOpts::delve_assets` (порядок корней — fill_v1).

## Панели

- **Сайд-панель**: секция проекта и статистика последнего fill (юниты,
  reused/reran, мс, размер кэша), кнопки операций, секции Selection / Units /
  Log. В пустом состоянии уровня активна только панель открытия (поля путей
  проекта/IR, недавние, Open; ошибка загрузки — красным тут же) и Log; после
  загрузки панель складывается в CollapsingHeader «Project: <имя файла>» с
  кнопкой Close (уровень и кэш сбрасываются, превью очищаются) и блоком
  «open another».
- **3D**: level-меш целиком (vertex colors из `@Cd`), орбита/pan/zoom мышью,
  Fit. Здесь же живут подсветка и соло юнита.
- **Top**: второй `GeometryPreview` в проекции `OrthoTop` (+X вправо, +Z вниз,
  §5.1) с тем же мешем; поверх — оверлей ImGui draw list через проекцию
  `viewProj` топ-превью. Слои-чекбоксы: контуры+id комнат, двери (зелёные
  open, оранжевые прочие dtype), владельцы стен, владельцы узлов, якоря
  (ромбики; `@label` — при наведении). Дефолт: комнаты/двери/якоря включены,
  владельцы выключены. Выделение рисуется отдельным ярким проходом независимо
  от слоёв.
- **Инфо-панель** (секция Selection, приёмка F9): клик ЛКМ по топ-пейну
  (без drag'а) выбирает комнату (point-in-polygon), стену/дверь (< 0.5 м до
  отрезка) или узел (< 0.5 м). Показывает параметры объекта и происхождение
  каждого значения цепочкой F12 (`format_prov`): у комнаты h/style/floor/ceil/
  wall_t, у двери dtype/h/frame/thick; у стены — владелец/стороны/двери, у
  узла — владелец/грани. Кнопки: Focus (камера обоих превью на bbox объекта),
  Highlight unit, Solo unit.
- **Панель юнитов** (секция Units): `FillResult.units` группами по слоту,
  действия над выбранным — Focus (bbox точек спана), Highlight (временная
  points-группа на копии меша + `highlightGroup`, только 3D), Solo (под-меш
  спана через `topo::deleteByMask` с инвертированной маской, только 3D;
  «Back to level» возвращает уровень).
- **Log**: последние записи fill — юнитов, точек меша, мс, reused/reran;
  ошибки операций — красным.

## Операции

- **Refill (reload project)**: перечитывает проект с диска, пересобирает IR из
  того же `LayoutData` (в `--ir` режиме — повторяет чтение файла) и наполняет
  через тот же `UnitCache` — в логе видно reused/reran (F8, D3). Камера
  сохраняется.
- **Re-layout**: generate заново (тот же seed, attempts=4) → новый
  `LayoutData` → IR → refill; неизменённые юниты приходят из кэша (приёмка
  D3). Недоступна в `--ir` режиме. Камера перефокусируется на сцену.
- Обе операции сбрасывают выделение и выбор юнита (id/спаны пересобираются).

## Лимиты v1

- Пикинг только в топ-вью; в 3D-виде выбора нет.
- Якоря — только в оверлее топ-вью (в 3D-рендере не рисуются).
- В `--ir` режиме с файлом `delve-ir/2` цепочки происхождения пусты (читатель
  их не восстанавливает): колонка происхождения показывает «-».
- Раскладка синхронна (малого уровня — быстрая); отмены из UI нет
  (F3-хук `request_cancel` в библиотеке есть, асинхронность — позже).

## Тесты

- `DelveViewer_smoke_layout`: `--smoke src/apps/DelveViewer/smoke_project.json`
  (генерация раскладки → IR → fill). Свой фикстурный проект, потому что
  `src/tests/data/d2_project.json` IR построить не может: роль corridor в нём
  переопределяет wall_t, и общие стены коридора с комнатами дают конфликт
  толщин — ошибку F4 по 5.2 (by design).
- `DelveViewer_smoke_ir`: `--smoke src/tests/data/d1_project.json --ir
  docs/d0/frozen_ir.json` (путь delve-ir/0, 17 комнат).
