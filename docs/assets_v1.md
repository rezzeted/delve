# Delve: библиотека ассетов v1 (D1.2)

Шесть ассетов слотов (`assets/`, контракты — `slots_v1.md` §2) + две библиотеки.
Проверка: `delve_assets_test` (R-A4: каждый ассет из своей фикстуры — без
E-диагностик, меш непуст, точное число якорей; паритет кодов `codes.pgg` ↔
`delve/project.h`).

## Библиотеки

- `codes.pgg` — `ST_*`/`RL_*`/`DR_*`/`DT_*`/`AK_*`/`ZP_*` def-константы
  + палитры `style_color`/`style_color_mortar` (неизвестный код — маджента,
  fail-loud). Значения нормативны (§1 слотов).
- `patterns.pgg` — `zone_style` (встык/штраба, слоты §3) + общий `elem_zone`:
  правило целого элемента (единогласные углы с отступом 1e-4, иначе пропуск;
  вне полосы зоны — стиль юнита, без экстраполяции).
- `ashlar.pgg` — палитры каменной кладки для v2-ассетов: `ashlar_lo/hi(style)`,
  `ashlar_color(style, shade, mot)` (ramp + mottle), `mortar_color(style, mot)`.
  Неизвестный стиль — маджента (fail-loud, как в `codes.pgg`).

## Ассеты и их пределы v1

- `rooms/fill_v1.pgg` — пол + плоский потолок боксами по bbox контура.
  ТОЛЬКО прямоугольники (`expect`, иначе ошибка); свет всегда, спавн только залу.
  Свод — не v1.
- `rooms/fill_v2.pgg` — плитка на mortar-постели (узоры медальон/бордюр/крест
  по rng), бочки в halls/crypts, потолок и якорь света только при `style_ceil != 0`.
  Пол, постель и потолок режутся контуром (`inside_polygon` по центрам ячеек,
  свес ≤ полплитки накрывает стена): фигурные планы (L, крест) — в пределах
  стен. Бочки — L-кучка у rng-вершины полигона (выпуклой или вогнутой 270°):
  сторона комнаты выбирается пробником, снаружи стен не бывает; до проёма не
  достают (двери ≥ 2 м от угла). Якоря — в центре bbox, если он внутри,
  иначе в «бочковом» углу. Плюс (C4) по одному blocker-якорю (`@kind=4`,
  `@range=0.36`) на бочку — занятые цилиндры для реестра декора; Delve при
  сборке снимает их в `FillResult::occupied`, в уровневые якоря они не
  попадают. Плюс (D5) вырезы в полу по входу `cuts` (точки `@range`, локальный
  кадр): под каждым колодцем выбиваются камни и постель (радиус +0.36/+0.60 м
  запаса под обрамление; потолок отдельным проходом не режется), ствол —
  облицовка `arc_shell` (r_in = cr−0.07, r_out = cr+0.005, y −0.66..−0.011)
  с почти чёрным дном на −0.62 и подложкой-кольцом (cr−0.02..cr+0.75,
  y −0.20..−0.045, шов 18.3°..377.7° под центром блока — снаружи ствола её
  видно сквозь выбивку), сверху фартук из ncuts·10 радиальных блоков
  (cr−0.02..cr+0.34, верх −0.008±0.0015, палитра ashlar). Радиус клампится
  снизу 0.15 (`max(cr, 0.15)`).
- `walls/body_v1.pgg` — растворный брус между гранями столбов, проёмы вырезаны
  `clip`, над проёмом перемычка. Высота = max(h_a, h_b) (R-A2).
- `walls/facing_v1.pgg` — ряды отделки: элемент 2×module, толщина 0.05, running
  bond со случайным направлением (`rng`), проёмы вырезаны, зоны через `elem_zone`.
  Элементы НЕ режутся: поперёк границы — пропуск (место закрывает раствор тела).
  Элементы выступают в сторону комнаты (локальный −Z при сегменте по обходу —
  поправка D2.3b: до неё выступали наружу, на дальнюю сторону стены).
- `walls/facing_v2.pgg` — кладка EmberEstate-вида: тот же курс-расклад, что у
  v1, но элемент — фасковый блок (`lib.parts.cbox`) на облаке якорей: цвет из
  `ashlar.pgg` в `@tint`, микро-jitter `@scale` приоткрывает швы до тела стены,
  fbm-мараморин в Cd. Редкий рельеф: ~3% блоков вдавлены в стену (темнее на
  20%), ~4% выступают (боссаж — инстансятся из углубленного блока 0.15 м,
  задняя грань остаётся в теле стены, камень не «висит»). `@style` ставится
  per-class инстансингом (см. ниже).
  Курсы обрываются под поясом (`rows = floor((h − 0.24)/module) − 1`), полоса
  `[rows·module, h − 0.24]` занята двухступенчатым карнизом из крупных плит
  (0.62 м, фронты 0.095/0.12 м); между кладкой, ступенями и поясом — теневые
  швы 3 мм, чтобы общая вертикальная плоскость (рез проёма, торец стены) никогда
  не резала два яруса с перекрытием по y (F11/elements, регрессия fac:c1).
- `walls/body_v2.pgg` — тело v1 + тёмный раствор из `ashlar.pgg`
  (`mortar_color`), видим в швах кладки. Брус укорочен до `H − 0.22`, сверху —
  пояс крупных притёсаных камней (~1.1 м, фаска 0.02, jitter длины/высоты/
  глубины; низ утоплен в брус на 0.02, бока выступают на 20 мм за блоки
  облицовки — ни одной копланарной пары). Пояс владеет полосой `[H − 0.24, H]`.
- `walls/node_v2.pgg` — столб-раствор (укорочен на 0.22) + грани кладкой (тот
  же приём, что facing_v2, зоны через `elem_zone_face`) + тот же редкий рельеф
  (вдавленные/выступающие блоки, у выступающих — углубленный блок 0.16 м) +
  тот же двухступенчатый карниз на открытых гранях (фронты +2 мм к facing:
  0.097/0.122) + угловой завершающий камень (0.784² — на 4 мм шире пояса body,
  низ утоплен на 0.02).
- `doors/opening_v2.pgg` — каменный портал: колонны-косяки из фасковых блоков
  (глубже стены на 0.20 — накрывают блоки облицовки), «joggled» перемычка
  (чередование ±2.5°, замковый камень шире и ниже), порог; gate = кованая
  решётка (прутья с наконечниками-«пирамидами» + 2 хомута). БЕЗ `@style`
  (контракт двери: нейтральная палитра; иначе F11/opening_voids ловит свои же
  фаски в полосе clear+frame). Ни одна пара граней не копланарна: перемычка
  длиннее и глубже косяков, порог длиннее обоих, наконечники утоплены в прутья
  на 3 мм (F11/elements, регрессия v2).
- `decor/lamp_v2.pgg` — фонари EmberEstate-вида: настенный собран локально
  (плита + крюк + кольца + каркас из `lib.parts.piece`/`lib.fixtures.rod/ring/
  pyramid_cap`; библиотечный `lib.fixtures.lantern` НЕ используется — в нём
  копланарные дубли плоскостей, F11/elements): каждая плоскость детали либо
  ≥1 мм от чужой, либо утоплена в соседнюю (решётка плоскостей — в шапке
  ассета), потолочный — `lib.ironwork.hanging_lantern` по `@n`; железо/стекло
  красятся раздельно (сплит по группе `lamp`), группы снимаются (`unmark`)
  перед сборкой. Якорь света — 0.30 м от стены / 0.45 м под потолком,
  `range = 6.0`.
- `decor/drain_v2.pgg` — круглая кованая решётка дренажа в полу (референс —
  `projects/iso/refs_tmp`): радиальная оконтовка из 12 блоков ashlar
  (`lib.plan.arc_shell` сектора с 2.4° швами, джиттер верха ±1.5 мм и радиусов,
  палитра пола комнаты с тёплыми ~10%), обод и внутреннее кольцо — плоский
  прокат со швом-сливом 0.6° (полный круг 0..360 дал бы дубль точки профиля),
  клёпки `lib.ironwork.bolt_heads`, сварная сетка плоских прутьев в 2 яруса
  (2.5 мм по вертикали, сварка на крестовинах, концы утоплены в обод на 15 мм),
  центральная бобышка и тёмный диск «воды» на y=±0.001 (выше самого высокого
  камня пола fill_v2 ≈ −0.002 — шахта под решёткой имитируется чёрным).
  Обод и низ блоков утоплены под y=0 — «врезано в пол»; пересечения с
  room_fill межъюнитные (F11/elements внутриюнитный). Якорей нет
  (`empty_points()`). При `pit = 1` (D5, под предметом реальный колодец
  fill_v2) обманки убираются: блоки оконтовки и диск «воды» не строятся,
  остаётся сама решётка (обод, кольцо, сетка, бобышка).
- `walls/node_v1.pgg` — столб + ряды по 2 элемента вширь на открытых гранях
  (грань уже 4×module — ряды всё равно кладутся, свес допустим). Локальная ось
  грани: `l = 0` в центре, `+l` направо от нормали; паритет с `+s` несёт `@flip`.
- `doors/opening_v1.pgg` — косяки/балка/порог/полотно; gate = + решётка.
  Решётка смещена к одной стороне полотна, планки и хомут — разной глубины,
  хомут не доходит до кромок полотна: ни одна пара граней не копланарна
  (поправка D2.3b, регресс `GateAssetHasNoDoubleGeometry`).
  Фиксированная нейтральная палитра (стиля нет, колонки `@style` нет).
- `decor/lamp_v1.pgg` — прибор вдоль нормали монтажа + РОВНО 1 якорь света
  (`range = 6.0`). Два варианта по `@n`: потолочный (штырь + плафон + лампа)
  и настенный факел (кронштейн + чаша + пламя, `|n.y| < 0.5`, длинная ось по
  нормали); одноимённые грани деталей не делят плоскость (F11 elements).

## Меш и якоря

- Точки меша: `@style: int` (код `ST_*`; у двери колонки нет — сборка даёт 0)
  + `@Cd: vec3` (превью; раствор — приглушённый вариант стиля).
- Якоря: `@kind`/`@dir`/`@range` (§1 слотов; kind: light=1, spawn=2, poi=3,
  blocker=4 — blocker сообщает занятый цилиндр и снимается Delve в реестр
  декора, в уровень не попадает); `@label` ставит Delve при сборке
  (PGG `set` не пишет строки, E204).

### Нормализация выхода под сборку F6 (v2)

Сборочный merge юнитов (delve_fill) требует от выхода `mesh`:

- нет непустых групп (D500) — библиотечные группы (`edge`/`iron`/`lamp`/`bulb`)
  снимаются `unmark`;- нет колонок vec2/vec4 (`uv` от `sweep`/`pyramid_cap` — `remove_attr`);
- нормали единообразно: любой «свой» `@N` снимается, финальный —
  `compute_normals(mode = smooth)` (у per-face точек cbox smooth == flat);
  corner-N от `cbox`/`compute_normals(flat)` наружу не выпускать (в сборке
  добивается нулями у юнитов без него — чёрные грани);
- служебные колонки (`@tint`, `@scale`, `@orient`) не выходить: `@tint`
  запекается в Cd и снимается.
- **`realize` материализует только `@tint`** (контракт builtin): `@style` точек
  инстансинга теряется. Поэтому стиль ставится per-class: облако режется
  `delete(cloud, where = @style != k)` по классам 1..5, каждый класс
  инстансируется и красится отдельно, затем merge.
- Дверь `@style` НЕ ставит (нейтральная палитра по контракту): иначе её
  собственные фаски попадают в полосу проёма (F11/opening_voids пропускает
  только грани со стилем 0).

Этот раздел проверяется машинно: `delve::lint_asset` (коды `delve/lint`)
прогоняет ассет с синтетическими входами слота и режет группы/vec2/vec4/
отсутствие `@style`/`@Cd`/`@kind` до полного fill — через MCP
`delve_asset_check` (пакет A2, docs/roadmap_v1.md).

## Фикстуры (R-A4, слоты §5)

Рядом с ассетом: `<stem>.fixture.json` (`{"params": {...}}`, значения —
param-text, `@path` относительно каталога фикстуры) + `*.points.json`
(`pgg-points/1`). Тест повторяет биндинги PggTool 1:1 (`parseParamText`).
