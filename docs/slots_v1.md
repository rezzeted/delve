# Delve: интерфейсы слотов v1 (D1)

Нормативный контракт между Delve и `.pgg`-ассетами (requirements R-A1–R-A9, §4–§5).
Версия интерфейсов: **1** (см. `slot_version`). Несовместимые правки — только через
новую версию (процедура миграции — открытый вопрос 7 requirements).

## 0. Гранулярность юнитов (открытый вопрос 1 — решено)

Принят дефолт из requirements: **комната (пол, потолок, наполнение), тело стены,
облицовка стороны, узел и дверь — отдельные юниты**. Плюс декор (по тегу) отдельными
юнитами. Облицовки одной стороны НЕ объединяются (пересмотр — если накладные расходы
на прогоны не уложатся в N5; замер — на D1).

## 1. Общие конвенции

- **Локальные координаты** (R-A9): юнит строится в своей локальной системе, метры,
  ось Y вверх. Мировое положение Delve применяет при сборке (F8); мировых координат
  во входе нет.
- **Выходы всех видов** (R-A2): `mesh: geo<mesh>` и `anchors: geo<points>`.
  Пустые якоря — допустимый пустой `geo<points>`, отсутствие выхода — ошибка R-A3.
- **Входная геометрия** — всегда `geo<points>` (`@P`, `y = 0`, если не сказано иначе).
  Производные величины вычислены в Delve и переданы готовыми (4.3).
- **`param rng_seed: int`** — у всех видов. Delve выводит из fill-seed проекта и
  стабильного id юнита: `seed = FNV1a_31(fill_seed || "/" || unit_id)`. Ассет делает
  `rng_from_seed(rng_seed)` сам; общий `rng` проекта юниту недоступен (5.6).
- **Лишние `param`** — только с дефолтами (R-A2); лишний `param` без дефолта —
  ошибка R-A3. Исключение (D5): лишний `param` geo-kind (`geo<points>` и т.п.)
  без дефолта допустим — значение даёт хост/фикстура (пустого geo-дефолта в
  языке нет); хост такой вход биндит всегда (пустым, если данных нет).
- **Версия** (R-A8): каждый ассет объявляет
  `def slot_version() -> (out: int) { out = 1 }` — тело обязано быть одним присваиванием
  int-литерала (v1 строго). Docstring у `slot_version` разрешён (он — не оператор тела,
  поправка D1.2). Delve читает значение статически при R-A3; несовпадение
  с требуемой (`1`) — ошибка слота до прогона.
- **Коды** (requirements 9.2): роли, стили, типы дверей, классы якорей — `int`-константы
  в общем ассете библиотеки `codes.pgg` (`ST_*`, `RL_*`, `DR_*`, `AK_*`). Значения v1 —
  в самой библиотеке; зарезервировано: `0` = «не задано» везде, КРОМЕ узоров перехода
  (§3: `ZP_BUTT = 0`, `ZP_CHASE = 1` — там 0 валиден; поправка D1.2).
- **Имена `param`/`output`** — точные, регистрозависимые (проверка R-A3 — по именам
  и типам, включая `geo`-kind).

### Стабильные id юнитов (5.6, F8)

Позиционно-независимы (поправка D3, `delve-ir/3`): id не содержит мировых
координат, поэтому перераскладка, сдвинувшая комнату, сохраняет id и ключи
кэша её юнитов — кэш переживает перераскладку (F8).

- `room:<room>` — наполнение комнаты (`room` — стабильный id из графа).
- `wall:<owner_room>:<edge>[.<k>]` — тело стены (`owner_room` — владелец
  общей стены, 5.2; `edge`/`k` — ребро и атом по атомизированному контуру
  владельца; `.k` — только если ребро держит больше одного атома, как у `fac:`).
- `fac:<room>:<edge>` — облицовка (`edge` — индекс исходящей вершины в контуре IR).
  Если ребро контура поделено T-стыками на несколько атомов (5.2) — суффикс `.k`
  (`fac:<room>:<edge>.<k>`, `k` — порядковый атом по обходу; поправка D1.1).
- `node:<owner_room>:<v>` — узел (`v` — индекс вершины в атомизированном
  контуре владельца: углы и T-вершины по обходу от вершины 0).
- `door:<a>-<b>` — дверь (`a < b` — стабильные id комнат).
- `deco:<tag>:<room>:<k>` — декор (`k` — номер размещения внутри комнаты,
  построчно; комнатно-локальный — поправка D3: был сквозной по уровню,
  перенумерация при смене набора комнат; размещение детерминировано от IR).

### Якоря (выход `anchors`)

Точки с атрибутами (все — points):

| Атрибут | Тип | Смысл |
|---|---|---|
| `@kind` | int | `AK_LIGHT=1` свет, `AK_SPAWN=2` спавн, `AK_POI=3` точка интереса, `AK_BLOCKER=4` занятый цилиндр (C4: снимается в `FillResult::occupied`, в уровневые якоря не попадает; эмитит только `room_fill`) |
| `@dir` | vec3 | направление (свет: ось пучка; спавн: взгляд; иначе `(0,-1,0)`) |
| `@range` | f32 | радиус света, м (`0` = н/п); у blocker — радиус цилиндра |

Человекочитаемую метку (`@label: string`) добавляет Delve при сборке (F6/F7 —
контекст юнита: id, роль); ассет её не ставит: `set` в PGG не пишет строки
(E204), строковые колонки в язык приходят только загрузкой из файла
(поправка D1.2).

### Колонки `mesh` (поправка D1.2)

Точки выходного меша несут (points):

| Атрибут | Тип | Смысл |
|---|---|---|
| `@style` | int | код `ST_*` стиля точки; читается тестом стыков (D1.5) |
| `@Cd` | vec3 | цвет точки для предпросмотра (палитра `codes.pgg`; раствор — `style_color_mortar`) |

Исключение: `door` v1 колонки `@style` не ставит (стиля нет — палитра фиксирована);
при сборке юнитов `merge` даёт её точкам нейтральный `0` («не задано», §1).

## 2. Контракты по видам слотов

Ключ слота — в скобках (R-A1: слоты по одному ключу).

### 2.1. `room_fill` — наполнение комнаты (ключ: роль)

Пол, плоский потолок на чистой высоте, якоря комнаты. Свод — не v1 (плоский потолок).

| `param` | Тип | Смысл |
|---|---|---|
| `contour` | geo\<points\> | контур комнаты, CCW с +Y, `y = 0`; на точке: `@edge_len: f32` (исходящее ребро, м), `@convex: bool` |
| `h` | f32 | чистая высота до потолка, м (5.5) |
| `role` | int | код роли (`RL_*`) |
| `style_floor` | int | код стиля пола (`ST_*`) |
| `style_ceil` | int | код стиля потолка (`ST_*`) |
| `rng_seed` | int | см. §1 |
| `cuts` | geo\<points\> | опционально (D5): вырезы в полу — точки в локальном кадре комнаты с `@range: f32` (радиус колодца, м); объявляется без дефолта (geo-экстра R-A2), хост биндит всегда (пустым при отсутствии вырезов) |

Выходы: `mesh` (пол + потолок одним мешем), `anchors` (свет потолочных светильников —
сами приборы ставит декор, см. 2.6; якоря spawn/poi роли — здесь).

### 2.2. `wall_body` — тело стены (ключ: конструктивный стиль владельца)

Конструктив между гранями столбов (5.2): длина тела = длина ребра − толщина стены.
Локальная система: ось стены — отрезок `seg.from → seg.to` (`y = 0`).

| `param` | Тип | Смысл |
|---|---|---|
| `seg` | geo\<points\> | 2 точки: концы тела (уже между гранями столбов), `y = 0` |
| `thick` | f32 | толщина стены, м (от владельца, 5.2) |
| `h_a`, `h_b` | f32 | чистые высоты комнат по обе стороны, м (R-A2) |
| `style` | int | конструктивный стиль владельца (`ST_*`) |
| `cuts` | geo\<points\> | проёмы: пары точек (концы отрезка на оси, `y = 0`); на точке `@h: f32` — высота проёма от пола (одинакова у пары) |
| `rng_seed` | int | см. §1 |

Высота тела = `max(h_a, h_b)` (считает ассет из входов; Delve передаёт обе высоты —
R-A2). Проём прорезается по тем же отрезкам, что в облицовках (5.3).
Выходы: `mesh`, `anchors` (пусто в v1).

### 2.3. `facing` — облицовка стороны стены (ключ: стиль отделки стороны)

Отделка одной стороны стены (5.2, 5.7). Локальная система: `l` — расстояние вдоль
`seg.from → seg.to` (направление обхода контура комнаты этой стороны), `y` — от пола.
Облицовка лежит плоскостью на грани тела со стороны своей комнаты (`offset =
thick/2` от оси к комнате передан готовым положением сегмента — сегмент уже
смещён на грань тела; поправка D2.3b про сторону — см. `n` ниже).

| `param` | Тип | Смысл |
|---|---|---|
| `seg` | geo\<points\> | 2 точки грани тела СО СТОРОНЫ своей комнаты, `y = 0`, в направлении обхода контура |
| `n` | vec3 | нормаль стороны, смотрящая В комнату (наружная для тела стены; единичная, горизонтальна). Поправка D2.3b: до неё IR клал сегмент и нормаль на дальнюю сторону стены (инверсия); ассет не читает `n`, элементы выступают в локальный −Z — т.е. в комнату (как у граней узла вдоль `+n`) |
| `h` | f32 | чистая высота своей стороны, м |
| `style` | int | стиль отделки стороны (`ST_*`, разрешён Delve по 4.2) |
| `module` | f32 | модуль ряда, м (5.7; высота ряда любого стиля кратна) |
| `cuts` | geo\<points\> | как у тела (те же отрезки, 5.3) |
| `zones` | geo\<points\> | куски зон переходов (см. §3; пусто, если стиля по соседству нет) |
| `rng_seed` | int | см. §1 |

Выходы: `mesh`, `anchors` (бра: якоря света настенных светильников — приборы ставит
декор; в v1 пусто, зарезервировано).

### 2.4. `node` — узел/столб (ключ: конструктивный стиль владельца)

Столб сечением `thick × thick`, центрированный в вершине сетки (5.2). Локальная
система: центр столба — origin, `y = 0` в основании.

| `param` | Тип | Смысл |
|---|---|---|
| `faces` | geo\<points\> | открытые грани: точка = центр грани (`y = 0`); на точке `@n: vec3` (наружная нормаль), `@h: f32` (высота комнаты, куда смотрит), `@style: int` (стиль отделки с учётом переходов), `@face: int` (номер грани в облаке — ключ зон, поправка D1.3) |
| `thick` | f32 | толщина (от владельца, = сечение столба) |
| `h_pillar` | f32 | высота столба = max высот смежных комнат (считает Delve, 4.3) |
| `style` | int | конструктивный стиль владельца (тело столба) |
| `module` | f32 | модуль ряда, м (тот же 5.7; ряды граней от пола; поправка D1.2) |
| `zones` | geo\<points\> | куски зон на открытых гранях (см. §3; локальная ось грани — горизонталь через центр грани, `l = 0` в центре, `+l` = направо от наружной нормали; паритет с `+s` несёт `@flip`) |
| `rng_seed` | int | см. §1 |

Закрытые грани (смотрят в тело стены) в `faces` не входят. Выходы: `mesh`, `anchors`
(пусто в v1).

### 2.5. `door` — дверь (ключ: тип двери)

Рама и полотно в проёме (5.3). Локальная система: ось проёма — `seg.from → seg.to`
(`y = 0`); проём симметричен относительно середины (позиция задана отрезком целиком).

| `param` | Тип | Смысл |
|---|---|---|
| `seg` | geo\<points\> | 2 точки: концы ЧИСТОГО проёма (`length - 2*frame` уже вычтен Delve, 4.3/5.3) |
| `h` | f32 | высота проёма от пола, м |
| `frame` | f32 | ширина рамы, м (для построения наличника вокруг чистого проёма) |
| `thick` | f32 | толщина стены (глубина откоса) |
| `dtype` | int | тип двери (`DR_*`) |
| `rng_seed` | int | см. §1 |

Выходы: `mesh` (рама + полотно + порог), `anchors` (пусто в v1; зарезервировано под
точку прохода).

### 2.6. `decor` — декор (ключ: тег)

Один предмет: светильник (`lamp`, `DT_LAMP=1`), решётка дренажа (`drain`,
`DT_DRAIN=2`), в будущем — мебель, мусор. Размещение считает Delve (шаг
светильников, правила `fill.decor` и т.п.), юнит строит предмет в точке.

| `param` | Тип | Смысл |
|---|---|---|
| `p` | geo\<points\> | 1 точка: позиция якоря предмета; `@n: vec3` — нормаль монтажа (потолок `(0,-1,0)`, пол `(0,1,0)`, стена — горизонталь) |
| `style` | int | код стиля (`ST_*`, разрешён Delve; напольному декору — стиль пола комнаты) |
| `tag` | int | код тега (`DT_LAMP=1`, `DT_DRAIN=2`, …) — один ассет может обслуживать несколько тегов ветвлением |
| `pit` | int | опционально (D5), дефолт 0: 1 = под предметом в полу реальный колодец радиусом `cut_r` правила (хост биндит только при вырезе); предмет строится утопленным, без обманки-«шахты» |
| `rng_seed` | int | см. §1 |

Выходы: `mesh` (прибор), `anchors` (у `lamp` ровно 1: `@kind = AK_LIGHT`,
позиция источника — не обязательно `@P` прибора; у предметов без света —
пусто).

## 3. Зоны переходов (5.7)

Кусок зоны в `zones` юнита: 2 точки (концы куска на локальной оси юнита, `y = 0`),
на обеих точках одинаковые атрибуты:

| Атрибут | Тип | Смысл |
|---|---|---|
| `@zone` | int | стабильный id перехода |
| `@pattern` | int | узор: `0` = встык, `1` = штраба (v1; рваный край и смешение — позже) |
| `@seed` | int | `rng` перехода (выведен Delve из id перехода, 5.7) |
| `@t_at_l0` | f32 | `t` зонных координат при локальном `l = 0` (`t = s − s0` предвычислен Delve) |
| `@flip` | int | `0`: `t` растёт с `l`; `1`: `t` убывает с `l` (`t(l) = t_at_l0 ± l`) |
| `@width` | f32 | ширина зоны, м (`t ∈ [0, width]`) |
| `@module` | f32 | модуль ряда (копия для `zone_style`; ряды от пола, 5.7) |
| `@style_a`, `@style_b` | int | коды стилей сторон A/B зоны (`ST_*`; поправка D1.2: без них ассет не знает, чем красить сторону B) |
| `@face` | int | ТОЛЬКО куски узла: номер грани в `faces`, которой принадлежит кусок (грани делят одно облако зон при независимых осях; красит `elem_zone_face`; поправка D1.3) |

Общий `def` узора (библиотека Delve, `patterns.pgg`), один на все юниты зоны:

```
def zone_style(pattern: int, t: f32, y: f32, seed: int, width: f32, module: f32) -> (out: int)
```

возвращает `0`/`1` — стиль A/B зоны. Семантика v1:

- `0` встык: `out = t < width * 0.5 ? 0 : 1`.
- `1` штраба: `course = floor(y / module)`; `tooth = module` (v1: зубец = модуль;
  «половина крупного элемента» — уточнением после D1); `b = width*0.5 +
  ((course % 2 == 0) ? -tooth*0.5 : tooth*0.5)`; `out = t < b ? 0 : 1`.
  (`seed` в v1 узорами не читается — зарезервирован под рваный край/смешение;
  передавать обязаны.)

**Правило целого элемента** (5.7): ассет кладёт элемент, только если весь его след
лежит в области своего стиля. Реализация v1 (`elem_zone` в `patterns.pgg`):
вычислить код стиля в углах следа элемента (в зонных координатах юнита; углы
с отступом 1e-4 внутрь следа — касание границы пропуском не считается);
разногласие → пропустить. Угол ВНЕ полосы зоны (`t ∉ [0, width]`) считается
стилем юнита (`own`) — зона за свои края не экстраполируется (поправка D1.2):
элемент поперёк края зоны пропускается честно, элемент за краем красится `own`.
Открытое место закрывает растворная сердцевина = тело стены / столб под облицовкой
(юнит облицовки/грани обязан оставить плоскость тела видимой там, где элемента нет;
тело красится растворным цветом через свой `style`).

## 4. Проверка ассета (R-A3)

Алгоритм Delve (статически, без прогона):

1. Парс + expand + typecheck ассета (корни импорта: проект → библиотеки Delve → `lib/` PGG).
2. Все обязательные `param` вида (§2) объявлены, типы совпадают (скаляры — точно,
   `geo` — с kind). Отсутствующий/неверный → ошибка `delve/slot` с именами слота,
   ассета, параметра, ожиданием и фактом.
3. Выходы `mesh`, `anchors` объявлены (имена — статически; их geo-kind —
   `mesh`/`points` — Delve проверяет при первом прогоне: PGG не отдаёт выведенные
   типы наружу, поправка D1.3).
4. Лишние `param` — все с дефолтами, иначе ошибка.
5. `def slot_version() -> (out: int)` существует, тело — `out = <литерал>`,
   литерал равен требуемой версии вида (v1: `1`).
6. Коды `role`/`style`/`dtype`/`tag` в дефолтах и теле — из `codes.pgg`
   (статически не форсируется в v1; convention + ревью).

## 5. Автономность (R-A4)

У скалярных `param` — дефолты (иначе ошибка R-A3, кроме geo). У каждого geo-`param` —
фикстура: рядом с ассетом `<stem>.fixture.json`:

```json
{"params": {"contour": "@contour.points.json", "h": 3.0, "rng_seed": 7}}
```

значения — в синтаксисе param-text (`@path` относительно каталога фикстуры,
`pgg-points/1`). Открытие ассета «самого»: PggViewer/PggTool, биндинги из фикстуры.
D1-тест открывает каждый ассет библиотеки через его фикстуру и требует отсутствия
E-диагностик и непустого `mesh`.
