# Delve: проект v1 (D2, F1)

Полный формат проекта (формат `delve-project/1`, JSON — открытый вопрос 3
закрыт в пользу JSON: строгая валидация R-P2 уже написана на nlohmann,
второй парсер не нужен). Проекты `delve-project/0` продолжают читаться
старыми правилами (без яруса раскладки). Ярус раскладки — целые клетки,
ярус наполнения — метры/коды (§4.1).

```json
{
  "format": "delve-project/1",
  "seed": 1,
  "layout": {
    "corridors": {"width": 2, "length": [3, 6]},
    "rooms_rect": {"w": [4, 8], "h": [4, 8]},
    "door_length": 1,
    "door_corner_distance": 1,
    "min_room_distance": 0,
    "catalog_budget": 512,
    "rooms": [
      {"id": "entry", "role": "entry"},
      {"id": "hall", "role": "hall", "tags": ["treasure"]},
      {"id": "c1", "role": "corridor"}
    ],
    "passages": [
      {"a": "entry", "b": "c1", "door": "open"},
      {"a": "c1", "b": "hall", "door": "gate"}
    ],
    "templates": [
      {"name": "grand_hall", "roles": ["hall"],
       "contour": [[0, 0], [10, 0], [10, 8], [4, 8], [4, 4], [0, 4]],
       "doors": "simple",
       "transforms": ["identity", "rot90", "rot180", "rot270"],
       "fill": {"h": 4.0}}
    ]
  },
  "fill": {
    "cell": 2.0,
    "wall_t": 0.6,
    "roles": {
      "*": {"h": 3.0, "style": "stone", "floor": "stone", "ceil": "plain"},
      "corridor": {"h": 2.6, "style": "brick", "wall_t": 0.6}
    }
  },
  "slots": {"room_fill": "rooms/fill_v1.pgg"},
  "asset_roots": ["assets"]
}
```

## Ярус раскладки (`layout`, обязателен в v1)

- `corridors`: параметрические шаблоны коридоров (R-C2): ширина `width`
  (клеток между осями стен, ≥1) × длины из диапазона `length` `[min, max]`
  (каждая ≥1, `min ≤ max`). Применяются только к роли `corridor`.
- `rooms_rect`: параметрические прямоугольные комнаты (R-C2): стороны из
  диапазонов `w`/`h` (`[min, max]`, каждая ≥1). Необязательный `roles`
  сужает применимость (по умолчанию — все некорридорные роли графа);
  роль вне списка обязана иметь явный шаблон (иначе ошибка R-G3).
- `door_length` (≥1), `door_corner_distance` (≥0): правило дверей по
  умолчанию для простых режимов (клетки, §4.1).
- `min_room_distance` (≥0): клеток между комнатами; передаётся edgar
  (`minimum_room_distance`, мягкое ограничение — штраф энергии, §9.1).
- `catalog_budget` (≥1, дефолт 512): максимум шаблонов
  (параметрических + явных); превышение — ошибка загрузки, размер
  каталога виден в диагностике F2 (R-C2).
- `rooms`: граф уровня (R-G1): `id` (непустая строка, уникальна),
  `role` (фиксированный набор), `tags` (массив строк, дефолт `[]`,
  в v1 хранятся, ни на что не влияют), `fill` (переопределения уровня
  комнаты, см. ниже). Пустой граф — ошибка. Коридоры в v1 только явные
  ролью; флаг «соединять коридорами» (R-G2) отложен.
- `passages`: связи (R-G1): `a`/`b` (id комнат, существуют, `a ≠ b`),
  `door` (тип двери, дефолт `open`). Дубликат неупорядоченной пары —
  ошибка (edgar дубликаты тоже запрещает). Тип двери переживает
  раскладку через ребро графа: результат edgar сокетов не несёт
  (`LayoutDoorGrid2D` — только комнаты и отрезок), Delve разрешает
  `dtype` по паре комнат проёма (R-G1).
- `templates`: явные шаблоны (R-C1): `name` (уникально), `roles`
  (≥1 роли, которым шаблон доступен), `contour` (≥4 целочисленных точек,
  ортогональные рёбра ненулевой длины, без трёх коллинеарных подряд,
  ненулевая площадь, простой многоугольник; обход любой — нормализует
  F2 под конструктор `PolygonGrid2D`), `doors`
  (`"simple"` = правило проекта; `{"length","corner_distance"}` =
  переопределение; `{"manual": [...]}` = конкретные отрезки в локальных
  координатах шаблона, концы обязаны лежать на контуре), `transforms`
  (допустимые трансформации, R-C4; дефолт — 4 поворота; пустой список =
  только identity, как в порте), `fill` (переопределения уровня шаблона).
  Сокеты edgar в v1 не используются (все `null` = совместимы).

Имена трансформаций: `identity`, `rot90`, `rot180`, `rot270`, `mirror_x`,
`mirror_y`, `diag13`, `diag24`. Отражения — только если авторское
наполнение их выдерживает (R-C4, на совести автора + ревью).

## Иерархия значений (4.2) в v1

Разрешаются `h`, `style`, `floor`, `ceil`, `wall_t` (толщина на роль —
новое в v1; `wall_t` на проекте — дефолт): комната → шаблон → роль →
проект. `roles["*"]` — дефолт уровня роли. Правила сторон (`side_rules`,
только стиль, как в v0) применяются поверх разрешённого стиля комнаты.
Граф и каталог в v1 только инлайн; внешние ссылки (R-P1) отложены.

## Проверки загрузки F1 (до любых вычислений)

- Строгость R-P2: неизвестный ключ, неверный тип, значение вне диапазона —
  ошибка с путём до ключа, ожиданием и фактом.
- R-G3: связность графа (BFS); коридор — ровно 2 соседа, оба не коридоры
  (иначе edgar бросит позже с худшей ошибкой); у каждой роли графа —
  хотя бы один шаблон (параметрический или явный с ролью в `roles`).
- Инварианты 5.4 (глобально-консервативно, точные — на F4/F11):
  `WT` = максимум всех заданных `wall_t` (проект, роли, шаблоны, комнаты);
  каждый `0 < wall_t < cell`; чистый коридор
  (`corridors.width × cell − WT`) ≥ `min_passage`; чистый проём
  (`door_length × cell − 2 × frame`) > 0 и ≥ `min_opening` (то же для
  каждого ручного отрезка и каждого переопределения `length`);
  `corner_distance × cell ≥ WT/2 + frame` (то же для каждого ручного
  отрезка — по расстоянию концов до ближайшего угла, и каждого
  переопределения). Явные шаблоны роли `corridor`: минимальная сторона
  bbox × cell − WT ≥ `min_passage` (консервативно).
- Бюджет каталога (R-C2): число параметрических
  (`len` длин + `w × h` прямоугольников с учётом сужения `roles`) +
  явных ≤ `catalog_budget`. Повороты множат инстансы на стороне edgar
  (пустой список трансформаций в порте = только identity).

## Сиды (5.6)

От seed проекта отщепляются `layout_seed = FNV1a_31("layout/<seed>")` для
раскладки и `fill_seed = FNV1a_31("fill/<seed>")` для наполнения
(`unit_seed`/`zone_seed` — от fill-seed, как в v0). Путь v0 (`/0`)
поведение не меняет (seed используется как fill-seed напрямую).
