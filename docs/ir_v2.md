# Delve IR v2 (D1–D2, F4/F5)

Построение из замороженного IR (`delve-ir/0`) + проекта наполнения (`src/libs/delve/ir.cpp`).
Без edgar: источник истины — `grid` замороженного IR; хранящийся там `contour` в метрах
игнорируется (поэтому смена `cell`/`wall_t` — без edgar, тест `IrCorner.RetuneWithoutEdgar`).

## Вход

- Комнаты — только прямоугольники (4 вершины, оси; фигурные — на D2, иначе ошибка F4).
- Двери — только в 1 клетку (§9.1: длинные — на D2), отрезок обязан лежать на контуре
  комнаты и быть попарно продублированным обеими комнатами с тем же отрезком.
- Обход нормализует Delve (§5.1): `area2 > 0` — реверс.

## Стены (§5.2)

- Атомизация: каждое ребро контура делится во всех вершинах, лежащих на его линии
  (T-правило 5.2), двери атомы НЕ делят (дверь — вырез, не стык).
- Атом = один юнит тела. Общий атом (комнаты с обеих сторон) — одно тело, владелец =
  min id комнат; наружный — своей комнате. Толщина — `wall_t` проекта (в v0 одна на всех;
  проверка «стороны разрешили разную толщину» ни во что не упирается — на D2 с толщиной на роль).
- id: `wall:<x0>,<y0>-<x1>,<y1>`, концы лексикографически min первым.
- Комнаты атома — слева/справа от оси `g0 → g1`; высоты обеих сторон хранятся
  (`h_a`/`h_b` для `wall_body`; у наружной вторая = высота владельца).

## Узлы (§5.2)

- Узел — в каждой вершине, где сходятся ≥2 стен (все углы комнат + все T-вершины),
  ровно один на координату. Владелец = min id смежных комнат.
- Грань открыта, если из вершины вдоль её нормали не уходит стена; иначе закрыта.
- Комната за открытой гранью — единственная смежная комната строго за гранью
  (строгое неравенство по касательной снимает неоднозначность на границах); нет — пустота.
- Длина грани на развёртке: `thick`, если вершина строго внутри ребра комнаты,
  в которую грань смотрит (T-грань); иначе 0. Для прямоугольников угловые грани
  в свою комнату не смотрят никогда.
- Стиль грани: в комнату — стиль стороны на развёртке (T-грань = стиль A; см. ниже);
  в пустоту — стиль владельца (экстерьер столба).

## Развёртки (§5.7)

- Одна развёртка на комнату: `s` в метрах вдоль обхода от вершины 0 (начало фиксировано
  раскладкой — id переходов не плавают при смене стилей).
- Облицовка занимает атом минус `thick/2` с каждого конца (грани столбов);
  T-грань — `[s_v − thick/2, s_v + thick/2]`; в обычных углах — зазор столба без граней.
- Стиль облицовки — уровень «сторона» 4.2: последнее совпавшее `side_rules`, иначе стиль роли.
- id облицовок: `fac:<room>:<edge>[.<k>]` (суффикс `.k` — если ребро контура держит
  больше одного атома; поправка к `slots_v1.md`, принято в D1.1).

## Переходы (§5.7)

- Ровно один переход на стык с разными стилями флангов (угол или T-стык);
  T-грань при разных флангах получает стиль A (входящий по обходу).
- Стили: A = входящая облицовка, B = исходящая. id — порядок по (room, s).
- Положение: `corner` — `[s_j − w/2, s_j + w/2]`; `wall` — на стороне B от края стыка
  (`[s_B0, s_B0 + w]`; выбор стороны B зафиксирован в v1).
- Обрезка: зона пересекается с доступным (интервалы участников минус проёмы дверей);
  обрезка — `shortened` + предупреждение; пустая зона — вырожденная в точке стыка.
  Пересекающиеся зоны соседних переходов (патологическая ширина) — предупреждение, не ошибка.
- Замыкание развёртки: стык «последняя → первая» разворачивается (`s1` может превысить
  периметр — честное развёрнутое значение). Ограничение v1: зоны шире удвоенного
  расстояния до начала обхода у НЕзамыкающих стыков режутся линейно (с предупреждением).
- Куски (`zones` облицовок/граней) самодостаточны: `t` меряется от НЕобрезанного `s0`
  (`t_at_l0 = l_origin − s0_orig`), `@width` — настроенная ширина; коды сторон A/B
  (`styles`) лежат на куске (ассет красит обе стороны, не зная соседей);
  `flip = 0` у облицовок (ось по `+s`), у T-граней 0/1 (ось грани = направо от
  нормали, слоты §2.4; поправка D1.2).
- `seed` перехода — из id (`zone_seed`).

## Двери (§5.3–5.4)

- Вырезы тела/облицовок — ПОЛНЫЙ сегмент двери (1 клетка); чистый проём (минус `frame`
  с концов) — только юниту двери. `@h` вырезов = `door_h`.
- Тип: всегда `open` (в замороженном IR нет id сокетов; §9.1).
- F4-ошибки (строить дальше нельзя): `clear ≤ 0`; отступ от угла `< thick/2 + frame`;
  дверь не на общей стене своих комнат; дверь через T-стык (при целых вершинах
  недостижимо — защита).
- Минимумы 5.4 (`min_passage`, `min_opening`) на F4 НЕ проверяются — это F11 (D1.4).

## Производное (§4.3)

- `corridor_clear[room]` = min сторона коридора в метрах минус толщина.
- Метрический контур комнаты = `grid × project.cell` (в IR не хранится — у F6 есть проект).

## Артефакт (F5)

- `delve-ir/2`: rooms / walls / facings / nodes / doors / transitions / warnings / derived.
  Порядок стабилен (по id; N6); запись→чтение→запись — побайтово (тест).
  Чужой `format` отклоняется с ожиданием и способом (перегенерировать из замороженного/проекта; N7);
  для `delve-ir/1` подсказка напоминает про int id.
- id комнат — строки: десятичная форма id замороженного IR (`room:0`, `door:0-1`);
  на D2 — id графа. Пустота в ссылках на комнаты — `null` (стены `rooms`, грани узлов).
- Сиды: `unit_seed` = FNV-1a(`"<fill_seed>/<unit_id>"`) & 2³¹−1 (slots §1).

## Границы v2 (что НЕ делает F4)

Прямоугольники; двери 1 клетка/`open`; одна толщина; линейная обрезка
сверхшироких зон (см. выше); правила сторон — только стиль (`side`/`adjacent_role`).
